执行摘要

在手工编码时代，为便于记忆与分类，编码往往把品类、属性、序号等信息全部塞进一段定长字符串里。这类编码本质上是“分类码”，它回答的是“这是什么产品”，适合配料、统计与检索，却无法支撑“这是哪一件、经过谁的手、现在在哪”这样的追溯诉求。当企业推进一物一码追溯管理时，编码的角色必须从静态身份证升级为动态履历载体，设计重心随之重构。

本规范提出“三层编码、两类用途”的通用框架：产品族码（SKU）作为后台主数据标识产品种类；单品码（UIN）作为核心，为每件产品赋予全局唯一、终身不变、不可推测的身份；追溯载体（明码 + 加密二维码或 RFID）将身份固化到实物上。三层之间经赋码与加密贯通，形成可采集、可验证的完整链路。

规范同时给出产品族码七段结构、单品码双码并行方案、包装层级父子关联模型、全流程六大采集节点、防伪防窜货机制、追溯深度分级、行业适配建议、数据字典与落地步骤。企业实施时应以“通用框架 + 自有字典”方式落地：分类树与属性字典按行业定制，编码规则与关联逻辑跨企业复用。

本规范为 Snowlio Suite 雪豹云追溯平台家族 中 Snowlio Uncia（中文名：雪豹码，简称 UNC） 一物一码生成系统的配套技术规范。Snowlio Suite 包含：Snowlio Trace（雪豹云追溯平台，负责全链路采集与查询）、Snowlio Uncia（雪豹码，负责编码生成与赋码引擎）、Snowlio UDI（UDI/GS1 合规模组）、Snowlio Tag（码图与标签打印）。本规范所定义的编码规则，是 Snowlio Uncia 生码引擎与 Snowlio Trace 追溯查询之间一致性的基础。

一、总则

1.1 编制目的

为统一企业产品在生产、仓储、物流、渠道与售后各环节的身份标识与数据采集规则，建立"一物一码、码随物走、全程可溯"的追溯体系，特制定本规范。本规范旨在解决三个核心问题：这是什么产品（产品族识别）、这是哪一件（单品唯一身份）、它去过哪里（全流程履历）。

本规范所描述的编码体系是一个"框架 + 字典"结构：分类骨架与编码规则在企业间通用，各企业只需维护自己的分类树与属性字典即可落地。它既适用于追溯深度较低的成本敏感型品类，也适用于药品、母婴等高合规要求品类。

1.2 适用范围

本规范适用于企业对其生产或销售的实物产品实施一物一码追溯管理，覆盖从原料入库、生产赋码、包装关联、仓储物流、渠道分销到消费者验真与售后召回的全生命周期。软件、服务类无形产品不适用本规范。

1.3 编制原则

  • 唯一性：每一个最小销售单元拥有全局唯一、不可复用的身份码。
  • 稳定性：码一经赋定，终身绑定该产品单元，不因流转、改包装而变更。
  • 安全性：码序不可推测、暗码加密，防止批量克隆与伪造。
  • 可采集性：编码可被条码、二维码或射频标签稳定承载，便于机器自动采集。
  • 可扩展性：分类与属性采用字典驱动，新增品类或属性不改动编码结构。
  • 合规性：预留与 GS1、国家药品追溯码等标准的映射字段，避免合规返工。

四、编码体系总体架构

本规范采用"三层编码、两类用途"的总体架构。

4.1 三层编码

第一层为产品族码（SKU），标识产品种类，属于后台静态主数据，由企业前缀、三级分类、属性段、版本与校验位构成，长期稳定不变。

第二层为单品码（UIN），标识具体单件产品，是本体系的核心。它由产品族码与生产动态信息（日期、工厂、序列）通过赋码规则生成，全局唯一、终身绑定、不可复用。

第三层为追溯载体，即承载单品码的物理介质，包括人眼可读的明码、机器可扫的加密二维码，或射频识别（RFID）标签。载体印刷或贴附于每件产品及其包装上。

三层之间的关系为：静态主数据加动态生产信息，经赋码生成唯一 UIN，再经加密形成可采集的载体，最终实现全链路可采集、可验证。

4.2 两类用途

编码按用途分为主数据码与实例码两类。主数据码回答"是什么产品"，稳定存于 ERP 与商品主数据系统；实例码回答"是哪一件、哪一批"，由主数据码追加批次与序列号构成，用于仓储、溯源与售后。两者共用同一套编码规则，仅粒度不同。

这一分离至关重要：更换包装或供应商不影响主数据码，而实例码能精确定位到具体单品与批次，满足溯源与精准召回需求。

五、产品族码（SKU）编码规则

5.1 编码结构

产品族码由七段构成，段间以连字符"-"分隔：

企业前缀-大类-中类-小类-属性段-版本-校验位

示例：HY-03-01-002-C:RD|S:XL|M:COT-V1-K

5.2 各段定义

段序段名长度字符集说明
1企业前缀2–4 位大写字母标识企业或品牌，集团多品牌可分别设前缀
2大类2 位数字一级品类，如 03 表示服饰
3中类2 位数字二级品类，如 01 表示上衣
4小类3 位数字具体品项，支持 999 个细分
5属性段变长键:值，管道符分隔颜色、尺码、材质等，按需增删
6版本2 位V+数字设计迭代，如 V1、V2
7校验位1 位字母数字防录入错误，采用 Mod-37 算法

5.3 属性字典

属性采用"单字母键 + 受控值表"方式，键固定、值可无限扩展，企业按需取用。属性值必须来自字典，禁止自由文本录入。

键含义常用值示例
C颜色RD 红、BK 黑、WH 白、BL 蓝
S规格/尺寸S、M、L、XL、500G、M8、12MM
M材质COT 棉、STL 钢、ABS、304 不锈钢
V电压/容量220V、12V、500ML
P包装/保质期BX 盒、CS 箱、12M（12 个月）
T型号/技术参数IP54、5G、8CORE、NRM（常温）

新增属性（如环保等级 E）只需在字典中增加一行，编码结构不变。属性按键名字母升序排列，确保同一产品唯一编码。

5.4 字符集与分隔符

  • 字符集仅使用大写字母与数字，字母中剔除 I、O，避免与 1、0 混淆。
  • 三级分隔符：连字符"-"分段，管道符"|"分属性，冒号":"连接键值，解析无歧义。
  • 编码总长度建议不超过 40 位，超出会影响条码密度与扫码体验。

六、单品码（UIN）编码规则

6.1 设计原则

单品码是一物一码的基石，必须满足四条硬约束：全局唯一、终身不变、不可推测、全程可采集。其中"不可推测"最易被忽视——若采用 HY260915000001、HY260915000002 这类连续流水号，造假者扫描少量产品即可推算编码规则，进而批量克隆。因此流水段必须随机化或整体加密。

6.2 双码并行方案

本规范推荐"明码 + 暗码"双码并行方案，兼顾人工核对与防伪要求。

明码（半结构化）：供人工识读、客服核对与手工录入使用，共 17 位，结构为：

企业码(2) + 生产日期(6) + 工厂线别(2) + 随机序列(6) + 校验位(1)

示例：HY260915A1X7K2M9C

其中生产日期采用 YYMMDD 格式；工厂线别由企业内部编码；随机序列以安全随机数生成，不按生产顺序递增；校验位采用 Mod-37 算法计算。

暗码（加密二维码）：供机器扫描与消费者验真使用，二维码内容为加密字符串，明文包含完整 UIN、防伪校验值与时间戳，经对称加密后生成。加密密钥由企业密钥管理系统统一管理，定期轮换。暗码不可被肉眼直接解读，也无法从外观推算相邻产品的码值。

6.3 方案对比与选择

方案码的结构优点风险/适用
A 结构化码企业码+日期+工厂+流水+校验离线可读部分信息流水连续易被推测，适用于低风险品类
B 纯随机码随机序列，信息全在后台最难伪造、无法推测依赖网络查询，适用于高防伪品类
C 双码并行明码半结构化 + 加密二维码兼顾人工核对与防伪推荐，为主流做法

企业应根据产品风险等级与扫码环境选择方案。生产环境网络条件良好、防伪要求高的，优先选方案 C；离线扫码场景多、防伪要求一般的，可选方案 A 但须对流水段做随机化处理。

6.4 赋码与绑定

赋码发生在成品生产完成、进入包装前。系统按规则批量生成 UIN 并写入码库，状态置为"已生成未绑定"；喷码或贴标设备将码加载至产品后，状态更新为"已赋码"；装箱扫描时完成父子关联，状态更新为"已关联"。码库应记录每个 UIN 的完整状态流转日志。

七、包装层级与父子关联规则

7.1 层级模型

追溯的难点不在码本身，而在码与货的绑定关系。产品包装通常分为单品、盒/中包、箱、托盘四级，必须逐级建立父子映射：

  • 单品码（UIN）：最小销售单元，是追溯的最小粒度。
  • 箱码（CASE）：标识一个装箱单元，关联其所含的 N 个单品码。
  • 托盘码（SSCC）：标识一个物流单元，关联其所含的若干箱码。

7.2 父子关联规则

  1. 装箱时必须逐一扫描每个单品码，系统记录"箱码 → 单品码列表"的包含关系。
  2. 组托时扫描各箱码，系统记录"托盘码 → 箱码列表"的包含关系。
  3. 任一层级的码均可通过父子映射向上定位所属批次、向下展开全部下级单品。
  4. 关联关系一经建立不得随意修改；确需调整的，须记录变更原因、操作人与时间。
  5. 装箱环节必须设置重扫校验与漏扫拦截：扫描数量与装箱单不符时，系统禁止封箱并告警。

7.3 精准召回

发生质量问题需召回时，只需输入问题批次或若干问题单品码，系统即可沿父子映射自动展开该批次下全部受影响单品及其当前流向（经销商、门店、区域），实现定向召回，避免扩大召回范围造成不必要损失。这是父子关联最核心的业务价值。

八、追溯载体与二维码规范

8.1 载体形态

  • 一维条码：承载明码，用于仓储、收银等高速扫描场景。
  • 二维码：承载暗码，用于消费者验真、溯源查询与防伪校验，建议使用 QR Code 或 DM 码。
  • RFID 标签：用于整箱、整托等非接触批量采集场景，标签内写入 SSCC 与箱码。

8.2 印刷与质量要求

  • 明码应清晰可读，字符高度不小于 2.5 毫米，印刷对比度满足扫码要求。
  • 二维码尺寸应根据印刷介质与扫码距离确定，最小模块宽度不低于 0.33 毫米。
  • 载体应避开产品包装的折痕、接缝与反光区域，防止扫码失败。
  • 印刷后须进行首件检验与在线抽检，扫码识别率应达到 99.5% 以上。

8.3 加密与密钥管理

暗码加密采用对称加密算法，密钥由企业密钥管理系统集中管理，按季度或按批次轮换。加密明文至少包含 UIN、防伪校验值与生成时间戳。消费者扫码时，系统解密后校验码值有效性、查询次数与地理位置，返回验真结果与追溯信息。

九、全流程数据采集节点规范

9.1 采集节点

全链路设置六大关键采集节点，每个节点扫码即写入一条追溯记录：

节点采集内容业务目的
原料生产原料批次、供应商、工艺参数建立生产履历起点
赋码关联UIN 与产品绑定关系确立单品身份
入库出库箱码、托盘码、仓库、时间库存与流向管理
渠道配送经销商、收货地址、物流单号流向追踪与防窜货
终端销售门店、零售扫码末端流向确认
消费者售后验真扫码、售后工单、召回登记验真、售后与召回

9.2 采集字段

每次扫码采集须至少包含以下字段：码值、采集时间、采集地点（GPS 或设施编码）、操作人（账号）、操作设备编号、动作类型（入库/出库/销售/验真等）、上下游关联码。所有记录写入不可篡改的追溯数据库，保留期限不低于产品保质期届满后两年。

9.3 正向查询与反向召回

正向查询按单品码可查到从原料到终端的完整履历；反向召回按批次或单品码可定位受影响范围与当前去向。两类查询均应支持在秒级内返回结果。

十、防伪与防窜货机制

10.1 防伪机制

风险应对机制
码被克隆复制暗码加密，一码一验，同一码被多地高频扫描时触发异常告警
码序被批量推测流水段随机化，码序不连续、不含规律
内部人员造假扫码日志全程留痕，谁在何时何地扫码不可抵赖
二维码被替换一物一码与包装序列号绑定，验真时校验一致性

10.2 防窜货机制

消费者或渠道扫码时，系统记录扫码地理位置，与该码授权销售区域进行比对。若扫码位置长期偏离授权区域，系统自动标记为疑似窜货并生成预警。企业可据此核查经销商流向，维护渠道秩序。

10.3 异常监控

系统应建立扫码行为分析模型，监测以下异常：同一码短时间内多次扫描、同一设备扫描大量不同码、扫码地理分布异常集中或分散、非工作时段批量扫码。异常触发后自动冻结相关码并通知风控人员核查。

十一、追溯深度分级与行业适配

11.1 追溯深度分级

企业应根据产品风险、合规要求与成本预算选择合适的追溯深度：

级别粒度说明适用
L1 批次级批次同批次产品共用一个批号，只追到批次成本敏感、低风险品类
L2 单品级单品每件产品唯一码，主流方案食品、化妆品、3C
L3 全链路单品+原料+工艺+渠道+消费者最完整，含工艺参数与消费者数据药品、母婴、高价值品

11.2 行业适配

  • 食品饮料：对齐 GB/T 34056，重点管理批次、保质期、冷链温度与召回，追溯深度以 L2 为主。
  • 药品/医疗器械：强制对齐国家药监 20 位追溯码，追溯深度 L3，数据须上传国家追溯系统。
  • 3C/电子制造：重点在序列号、保修期与售后溯源，追溯深度 L2，常与售后系统打通。
  • 化妆品：重点在防伪与防窜货，追溯深度 L2，消费者扫码验真为主要触点。

十二、数据字典

追溯系统的核心数据表字段定义如下：

字段名类型长度说明
UIN字符串17–20单品唯一码，主键
SKU字符串≤40产品族码，外键关联产品主数据
LOT字符串12生产批次码
PARENT_CODE字符串20上级包装码，顶层为空
PACK_LEVEL枚举—包装层级：单品/盒/箱/托盘
STATUS枚举—码状态：已生成/已赋码/已关联/已销售/已核销
PROD_DATE日期8生产日期，YYYYMMDD
FACTORY字符串2工厂线别编码
LOCATION字符串20采集地点，GPS 坐标或设施编码
OPERATOR字符串20操作人账号
ACTION枚举—动作类型：入库/出库/销售/验真/召回
SCAN_TIME时间戳—采集时间，精确到秒
ENCRYPTED_CODE字符串变长暗码加密串

十三、实施与落地

13.1 实施步骤

  1. 确定范围：明确追溯深度与合规要求，梳理需纳入追溯的产品线。
  2. 建立字典：构建三级分类树与属性字典，确定各品类所需属性及允许值。
  3. 设计编码：确定 UIN 结构、加密算法、校验方式与版本升位策略。
  4. 建设产线：部署赋码设备（喷码/贴标）与关联采集系统，完成父子关联。
  5. 上线平台：建设追溯查询平台，打通 ERP、WMS 与渠道系统，开放企业端与消费者端查询。

13.2 关键成败点

一物一码项目失败大多不在编码设计本身，而在赋码准确率与关联完整率。装箱时漏扫一个单品，整箱追溯链即断裂。因此必须在产线设置重扫校验、漏扫拦截与异常告警，并定期盘点码库状态与实物的一致性。

13.3 治理规则

  • 分类码只增不改、停用不复用，避免历史数据歧义。
  • 编码由系统按规则自动生成，禁止人工手编或篡改。
  • 外观或包装变化升版本，结构或功能变化升小类。
  • 校验位与加密算法变更须全量回归测试，确保历史码可解析。
